## 2. Constats CRITIQUES

### C-1 — Rate limiting totalement contournable (`trust proxy: true`)
- **Fichier :** `backend/api/src/index.js:68` + `src/lib/rateLimit.js:17-30` (`clientIp()` préfère `req.ip`).
- **Problème :** avec `trust proxy = true`, Express fait confiance à **toute** la chaîne XFF ; `req.ip` = maillon le plus à gauche = **valeur falsifiable par le client**. Le commentaire « passerelle Render : X-Forwarded-For fiable » est faux : Render n'ajoute qu'**un** hop.
- **Impact :** brute-force de `admin-login` (20/5min), énumération de matricules séquentielles, spam d'inscriptions (`register-director` 5/5min), contournement de toutes les clés IP. Seules les limites par identifiant survivent (10/5min).
- **Correctif :** `app.set("trust proxy", 1)` ; dériver l'IP du **dernier** maillon XFF ou de `req.socket.remoteAddress` ; ajouter un test de non-régression (XFF arbitraire ⇒ `req.ip` inchangé).

### C-2 — `MIGRATIONS_A_APPLIQUER.sql` : bundle de prod divergent et cassé
- **Fichier :** `MIGRATIONS_A_APPLIQUER.sql` (racine, **tracké git**, commit `c89b022`), 1 553 lignes.
- **Vérifié :** ligne 25 `p_birth_daate date` au lieu de `p_birth_date` → `create or replace function` **écrase** la fonction saine avec une version cassée (référence un paramètre inexistant) → **inscriptions élèves hors service** (réparé ensuite par 00036/00038, mais toute application partielle/répétée dégrade la prod).
- **Vérifié :** le bundle = 00028 + 00035→00042 uniquement ; il **saute 00029→00034** (`secretaire`, `block_student_bulletins`, `platform_settings`, timetables…). Or `00041` lit `school_settings.block_student_bulletins` (créée en 00030) → **le bundle échoue à 00041 si 00030 n'est pas appliquée**.
- **Impact :** dérive silencieuse prod ↔ repo ; état prod inconnu ; la CI (`supabase db reset`) ne teste que des installations fraîches, pas une prod en retard.
- **Correctif :** `git rm MIGRATIONS_A_APPLIQUER.sql` ; lister l'historique réel (`supabase migration list --db-url …`) ; sauvegarder ; `supabase db push` dans l'ordre (00029→00042) ; si un rattrapage est nécessaire, le générer depuis `migrations/` (jamais à la main).

## 3. Constats HAUTES

### 3.1 Backend / API

**H-1 — Console admin sans moindre privilège (rôle `agent_suivi` = lecture totale)**
`src/lib/authAdmin.js:77-89` n'exige que `status === "ACTIF"`. Résultat : un agent de suivi peut lire **toutes** les données personnelles (directions, téléphones, e-mails), les effectifs, les abonnements (`adminSchools.js:19`), le journal d'audit complet **avec payloads** (`adminAudit.js:23-120`), `payment_ref` (`adminFinances.js:189`), et les clés `rate_limits` contenant des e-mails (`adminSecurity.js:174-178`). → Introduire des permissions par rôle ; réserver PII/paiements/audit aux `admin+superadmin` ; masquer `payment_ref` et les clés de rate limit aux autres ; paginer/exporter côté superadmin.

**H-2 — PATCH écoles modifiable par tout agent admin (cross-tenant)**
`src/routes/adminSchools.js:93-155` : seuls `registrationOpen`/`autoApproveStudents` sont réservés superadmin ; `name/city/address/phone/email/cycles` sont modifiables par **n'importe quel agent** sur **n'importe quelle école**. → Restreindre le PATCH (hors statut) à `admin+superadmin` ; journaliser un diff champ-à-champ.

**H-3 — Authentification admin sans MFA ni verrouillage ; DoS ciblé par compte**
`src/routes/adminLogin.js:49-74` : une seule barrière (mot de passe). La clé `admin-login:id:<email>` (10/5min) permet d'épuiser le quota d'un admin légitime (429 en boucle) ; combinée à C-1, illimitée. → TOTP (MFA) ou verrouillage progressif + alerte sur `admin_login_failed` ; ne pas bloquer brutalement sans signal.

**H-4 — Purge d'école : confirmation devinable publiquement**
`src/routes/adminSchools.js:190-264` (l.216) : la confirmation retombe sur `school.name` (public) si pas de matricule. Suppression en cascade (élèves, notes, paiements) sur une ingénierie sociale. → Exiger matricule **et** nom, ou code à usage unique au superadmin ; soft-delete avec fenêtre de grâce ; vérifier les orphelins Auth après coup.

**H-5 — Inscriptions publiques ouvrent un abonnement « Premium » gratuit 1 an, sans encaissement ni e-mail vérifié**
`src/routes/registerDirector.js:52-59, 68` (`email_confirm: true` forcé). Avec C-1 + absence de CAPTCHA : création massive d'écoles gratuites, MRR/ARR faussés (`adminStats.js:54`, `adminFinances.js:84` calculent sur ces « ventes »). → Offre « Découverte » plafonnée seule en auto-activation ; vérification e-mail avant activation ; CAPTCHA ; cap global/jour ; exclure les non-payés du MRR.

### 3.2 Frontend

**H-6 — Mots de passe staff transmis via URL WhatsApp**
`features/staff/StaffCredentialsModal.tsx:20-34, 57-60, 103` ; `resetStaffPassword` (`authService.ts:333-353`) idem. Le mot de passe (définitif, choisi par la direction) part dans l'historique navigateur, les serveurs WhatsApp, tout appareil WhatsApp Web ; copie dans le presse-papier persistant. → **Ne jamais mettre un secret dans une URL.** Affichage unique + remise en main propre, ou lien de définition de mot de passe à usage unique ; exploiter `mustChangePassword` (déjà implémenté) au lieu d'un mot de passe partagé.

**H-7 — `child_code` + nom de l'enfant dans la query string**
`StudentSignupForm.tsx:76-79` (`&code=`), `ParentSignupForm.tsx:67` (`&eleve=`), lu par `pages/auth/SignupSentPage.tsx:8-13`. Le `child_code` est un **bearer** rattachant un compte parent aux données scolaires d'un mineur (notes, bulletins, paiements, absences). Présent dans historique, logs proxy/Render, `Referer`, captures. → `navigate(state)` (mémoire, non persistée) ou stockage éphémère purgé ; supprimer `code`/`eleve` de l'URL.

**H-8 — Routes `/admin/*` sans contrôle de rôle côté client**
`App.tsx:127-149` n'applique aucun `adminGuard` ; `routes/adminGuards.tsx:48-50` est **du code mort** (0 usage vérifié) ; `ADMIN_ROUTE_ROLES` ne couvre que 3 clés ; seuls des boutons sont masqués (`AdminAgentsPage.tsx:59`). Tout agent authentifié (même `agent_suivi`) ouvre `/admin/agents`, `/admin/finances`, `/admin/parametres`. → Brancher `adminGuard(...)` par route (le backend re-vérifie l'auth — `requireAdminRole` — mais **aucun contrôle de granularité**, cf. H-1) ; journaliser les 403.

**H-9 — Rules of Hooks violée (erreurs React confirmées à l'exécution)**
`routes/guards.tsx:33-41` : `usePageMeta({ noindex: true })` appelé **après** `if (loadingSession) return …` (l.37-38). Confirmé via Playwright sur `/connexion` : *« React has detected a change in the order of Hooks… »* et *« Internal React error: Expected static flag was missing »* — sur **toutes** les pages publiques d'auth (`/connexion`, `/inscription`, `/mot-de-passe-oublie`, `/inscription/premium`, `/inscription-envoyee`). → Remonter le hook avant tout `return` (patron déjà utilisé ailleurs dans le codebase).

**H-10 — Frontend : build monolithique + hydratation intégrale **double** par login**
- `vite.config.ts:23` (`vite-plugin-singlefile`) : **1,59 Mo inliné** (432 Ko gzip) ; les 40+ `lazy()` d'`App.tsx` n'économisent rien ; Recharts payé par la landing ; `script-src 'unsafe-inline'` forcé (CSP affaiblie) ; zéro cache granulaire.
- `services/authService.ts:60,135,148` → `currentSession()`/`login()` appellent `hydrateAll()` puis re-passent par `currentSession()` ⇒ **2× téléchargement complet de la base** à chaque connexion ; `hydrateAll()` tire **16 tables** (`select *` paginé 500, plafond 100 000 lignes/table, `db.ts:354-374`) ; ~45 ré-hydratations complètes après chaque mutation ; `listStaff()` re-télécharge `profiles` à chaque appel. Sur une école réelle : **dizaines de Mo par connexion** + parsing bloquant.
- → Requêtes ciblées/paginées côté serveur, TanStack Query (ou équivalent) avec invalidation précise, abandon de `vite-plugin-singlefile` (build multi-fichiers + CSP stricte).

**H-11 — Types Supabase générés jamais branchés**
`lib/supabase.ts:14` : `createClient(url, key)` **sans `<Database>`**. `types/database.generated.ts` (1 014 lignes) et `types/database.ts` (206 lignes) : **0 import** (vérifié). Conséquence : chaque `.rpc()`/`.from()` renvoie `any` → ~25 mappers `r: any`, 29 `: any`, 8 `as any`, 14 `as unknown as`, **zéro validation runtime** (enums `role/status/kind` jamais vérifiés, `mapSubscription` force `status:"ACTIF"`, `Number()` → `NaN` silencieux). → `createClient<Database>()`, mappers typés, Zod/Valibot aux frontières RPC ; supprimer le fichier « manuel » (dérive) ; régénérer les types en CI.

**H-12 — `npm run lint` hors service + règles de sécurité coupées**
`frontend/eslint.config.js` importe `typescript-eslint` **absent de package.json** (vérifié : `ERR_MODULE_NOT_FOUND`) ; `no-explicit-any: off`, `ban-ts-comment: off`, `exhaustive-deps: off` via un **faux plugin `react-hooks` inline** (le vrai plugin n'est pas installé) ; `eslint-plugin-react` déclaré mais non utilisé. → Aucune garde automatique ; le bug H-9 est passé inaperçu. → Installer `typescript-eslint` + `eslint-plugin-react-hooks`, réactiver les règles (warn→error), brancher en CI.

### 3.3 Base de données (Supabase / Postgres / RLS)

**H-13 — `MIGRATIONS_A_APPLIQUER.sql` saute 00029→00034 (prérequis des migrations de durcissement)**

Manquent notamment : rôle `secretaire` (00029 — requis par les policies et `finish_staff_registration`), `block_student_bulletins` (00030 — requis par 00038 et **00041**), `platform_settings` (00031), `subscription_requests` (00032), timetables (00034). → Appliquer dans l'ordre **après** réconciliation de l'historique ; le bundle tracké est un piège opérationnel (mojibake inclus).

**H-14 — `subscription_status_of` : surcharge au lieu de remplacissement → correction 00038 inerte**
`00038_durcissement_audit_vague3.sql:29` crée `subscription_status_of(uuid, timestamptz)` ; la fonction réelle appelée par `subscription_info` est `subscription_status_of(uuid, date, date default current_date)` (00002:67). La « correction » est une **surcharge distincte jamais appelée** ; la vraie fonction ne retourne **jamais** `EXPIRE_BIENTOT` ; le `revoke/grant` (l.42-43) ne porte que sur la surcharge. → Supprimer la surcharge ; ajouter la branche `EXPIRE_BIENTOT` dans la vraie fonction ; dropper la fonction morte.

**H-15 — Policy `admin_agents_select_superadmin` : récursion RLS infinie**
`00024_admin_agents.sql:77-85` : la policy fait `exists (select 1 from public.admin_agents …)` **sur la table protégée**, sans fonction `SECURITY DEFINER` → Postgres détecte la récursion (**erreur 42P17**) → **tout SELECT `authenticated` sur `admin_agents` échoue** (y compris la policy self). Seule la `service_role` (bypass RLS) fonctionne — d'où la non-détection. → Fonction `admin_is_active_superadmin()` en `SECURITY DEFINER set search_path=''` (pattern 00002) ; ou restreindre la lecture au self + service_role.

**H-16 — `config.toml` : inscription publique directe ouverte (contredit le design « comptes créés uniquement via API »)**
Vérifié : l.179 `enable_signup = false` (intention) **mais** l.224 `[auth.email] enable_signup = true` (**le flag effectif**), l.229 `enable_confirmations = false`, l.231 `secure_password_change = false`, l.185 `minimum_password_length = 6`, l.188 `password_requirements = ""`, l.76 `network_restrictions enabled = false`, l.160 `site_url = "http://127.0.0.1:5173"`, Studio activé. → N'importe qui peut appeler `/auth/v1/signup` directement (email non vérifié, hors rate-limit métier, hors flux d'approbation). → `enable_signup=false`, `enable_confirmations=true`, `secure_password_change=true`, min 8 + `lower_upper_letters_digits` ; `config.production.toml` distinct (site_url prod, network restrictions, Studio off).

### 3.4 Infra / CI / CD

**H-17 — CI cassée et aveugle au backend**
`.github/workflows/ci.yml` : (a) l'étape `audit:front` **plante** (`TODAY_ISO` supprimé du code ; harnais `frontend/scripts/audit-parite.mjs` obsolète → `TypeError: Cannot read properties of undefined`, vérifié en exécutant `npm run audit:front`) → CI rouge « tolérée » ou contournée ; (b) **le backend Express n'est jamais installé ni vérifié** (`service_role` !) — aucun `npm ci`, aucun `node --check` ; (c) pas de lint (pourtant des scripts existent), pas de `npm audit`, pas de tests ; (d) manque `permissions:`, `concurrency:`, `timeout-minutes:` ; (e) `node-version: 22` non épinglé par la repo (pas de `.nvmrc`/`engines` racine/frontend). → Réparer ou sortir l'étape du gating ; ajouter `npm ci` + `node --check` pour l'API (ou la réintégrer aux workspaces), `npm run lint`, `npm audit --omit=dev --audit-level=high` ; `permissions: contents: read` ; `timeout-minutes: 15`.

**H-18 — Actions GitHub non épinglées (supply-chain)**
`ci.yml:17-38` : `actions/checkout@v4`, `actions/setup-node@v4`, `supabase/setup-cli@v1` (tag majeur très mutable) **et `version: latest`** pour la CLI Supabase → builds non reproductibles, réécriture de tag = code arbitraire en CI avec accès au repo. → Épingler chaque action par **SHA complet** (`…@<sha> # vX.Y.Z`), figer la version de la CLI, activer Dependabot/pinact.

**H-19 — Aucun en-tête HTTP de sécurité ; clickjacking non mitigé**
`render.yaml` (static site) : seulement `routes` rewrite + `envVars` — **aucune section `headers`**. La CSP existe en `<meta>` (`index.html:12-15`) mais **`frame-ancestors` y est ignoré par les navigateurs** (vérifié : avertissement console) → clickjacking réel. Manquent aussi : `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy`, CSP **en header** (et `connect-src` autorise `http://localhost:*`/`ws://localhost` en prod — vérifié l.14). → En-têtes via Render/CDN (Cloudflare) ou passer le site derrière un web service ; CSP header avec `frame-ancestors 'none'` ; retirer localhost de la CSP prod.
